Проект: репозиторий `business-financial-os` (React + TS + Vite + Supabase). Полное ревью лежит в `reviews/2026-10-19-review.md`, список доработок — в `reviews/BACKLOG.md`.

**Задача: исправь только серьёзные ошибки ниже.** Ничего лишнего не трогай. По каждой ошибке: прочитай код, исправь, прогони `npm i && npm run build` и тесты. Потом коммит и пуш в рабочую ветку.

**A. Потеря и порча данных**
1. `src/lib/storage/supabaseFinanceRepository.ts:110-121` — `save()` удаляет на сервере бизнесы, которых нет в локальном state (две вкладки или сбой `load()` стирают данные). Убрать неявное удаление: удалять только явно по id (`removeBusiness`/`resetAll`). Если `load()` упал (`:58`, `:68`), бросать ошибку и блокировать запись, а не возвращать пустой state.
2. `src/lib/demo/demoBusiness.ts:12` — у демо фиксированный UUID, общий для всех пользователей, поэтому у второго пользователя upsert падает на RLS и не сохраняются все его бизнесы. Генерировать `crypto.randomUUID()`.
3. `src/features/finance/PnLRow.tsx:32`, `src/features/cashflow/CashFlowRow.tsx:17` — неконтролируемые инпуты: после переключения бизнеса в полях остаются старые цифры, и blur записывает их в новый бизнес. Сделать `key={activeBusinessId}` на `<Outlet>` в `AppShell.tsx:31` или контролируемые инпуты.
4. `src/store/businessStore.ts:185-189` + репозиторий — параллельные `save()` перезаписывают друг друга. Нужна очередь или debounce примерно 500 мс. Ошибку сохранения показывать в UI («Ошибка синхронизации»), а не только в `console.error`.
5. `src/pages/SettingsPage.tsx:67` — confirm говорит «удалить из браузера», а на деле стирает все облачные бизнесы. Исправить текст и потребовать подтверждение вводом названия.
6. `src/store/authStore.ts:26-34` — гостевые данные браузера молча заливаются в любой вошедший аккаунт и не чистятся. Спрашивать пользователя и чистить localStorage после переноса.

**B. Сломанные сценарии**
7. `src/App.tsx:46` — ссылка подтверждения регистрации открывает экран «Установите новый пароль». Проверять только `type=recovery`.
8. `src/store/authStore.ts:63-76` — async callback в `onAuthStateChange` (риск deadlock), hydrate на каждый `SIGNED_IN`, двойная подписка под StrictMode. Сделать callback синхронным (`setTimeout`), hydrate только при смене `user.id`, отписка в cleanup.
9. `src/store/businessStore.ts:221-235` — у только что созданного бизнеса `myRole === null`, и владелец попадает под PIN-гейт. Проставлять роль `owner` при создании.
10. `src/pages/LandingPage.tsx:102-106,147` — якоря `#features` под HashRouter редиректят на `/`. Сделать `scrollIntoView`.
11. Демо: `src/lib/demo/demoBusiness.ts` — `protectedRoutes: []` (сейчас разделы закрыты неизвестным PIN). `DailyDigestModal` в демо не показывать.

**C. Безопасность Supabase** (новая миграция `supabase/003_*.sql`, старые файлы не править)
12. `002_team_access.sql:185-206` — инвайт привязывается до подтверждения email. Привязывать только при `email_confirmed_at is not null`.
13. `002_team_access.sql:167-179` — `create_invite` позволяет узнать, какие email зарегистрированы. Возвращать одинаковый ответ и валидировать `p_allowed_domains`.
14. `002_team_access.sql:318-376` — `update_business_section` принимает любой jsonb. Проверять `jsonb_typeof` по ключам.
15. `supabase/functions/ai-cfo/index.ts` — нет лимитов и проверки размера и `history`, клиенту отдаётся текст ошибки Yandex. Добавить ограничение тела, валидацию, общий текст ошибки и rate-limit по `auth.uid()`.
